Estudos Git

Anotações

Comandos

  • git status - Mostra o status atual do git, mostra se tem arquivos para commit, se tem algum arquivo para salvar e etc.
  • git init - Inicia um novo projeto git.
  • git add - Adiciona o arquivo no projeto git.
  • git add . - Adiciona todos os arquivos dentro do projeto de uma só vez.
  • git commit - Comita os arquivos alterados do projeto, pode se utilizar a flag "-m" para adicionar uma mensagem no commit (Importante comentar as alterações para você ver o que foi realizado.).
  • git commit -a - Comita varios arquivos de uma vez.
  • git remote - Utilizado para acessar um git remotamente.
  • git push - Salva o arquivo / atualizações no Repo do github.
  • git pull - Puxa as atualizações do projeto no git, geralmente utilizado em projetos em grupo, ou buscando de outra máquina.
  • git clone - Clona um repositório do GitHub, geralmente utilizado quando ingressamos em um novo projeto.
  • git rm - Deleta o arquivo do projeto, esse comando não isola um arquivo do projeto ou monitoramento do git, o arquivo realmente é excluido.
  • git log - Mostra as informações dos commits realizados no projeto. (utilizar q para sair do log).
  • git mv - Permite mover e alterar o nome do arquivo. Funciona de forma similar ao crt+x que tira o arquivo e deixa na memória até a fase de colar.
  • git checkout - Volta ao estado anterior. Precisa tomar atenção, pois depois disso não podemos utilizar o ctrl+z. (esse comando pode ser um pouco confuso, então em uma atualização o git separou a função em git switch - cc para criar uma nova branch e git restore para restaurar o arquivo.).
  • git reset --hard - Volta o arquivo no tempo e apaga tudo o que foi feito. Pode utilizar o id do commit da versão estável para apagar todo o restante feito a partir dali.
  • gir branch - Visualiza as branchs.
  • git branch (nome) - Cria um novo Branch.

Orientações

  • Repositório - É onde o codigo vai ser armazenado (projeto).
  • .gitinore - Arquivo recomendado para informações ou pastas sensíveis que por segurança é melhor deixar fora do repositório. Podemos destacar pastas e categorias de arquivos que devem ser ignoradas pelo git.
  • Branch - É uma versão separada do projeto para fim de organização, utilizado para criações de novas features dentro do projeto sem trabalhar dentro do código main, assim isolando testes, correções e etc. Depois da nova feature ou atualização estiver estável, unificamos a branch com branch master.
